NODE-1 wrong (code comment): cmd/server/main.go 42-45 says the per-connection deadlines mean "handler goroutines cannot accumulate without bound behind a saturated event loop (… findings #10)". findings.md #10 says a saturated loop makes handler goroutines block indefinitely and pile up; TODO.md C7 keeps #10 open. Code: node/node.go enqueue, awaitAdmission, Snapshot and GovernanceView wait only on quit, never on request.Context(), so a deadline cannot free a handler waiting on the loop. Experiment (scratch cmd/wrapstall): node without its loop started, cmd/server's timeouts cut to 2 s, 1,500 GET /hdls/accounts with a 300 ms client timeout: 1,503 goroutines right after, 1,502 six seconds later. Fix the comment: "Per-connection deadlines: a client that stalls mid-request or never drains its response is disconnected instead of holding a goroutine forever. They do not free a handler that waits on the event loop, so a flood still piles goroutines up behind a saturated loop; only a rate-limiting proxy bounds that (findings #10)."

NODE-2 missing (doc): docs/api.md Relay bullet (95-98) and the POST table's cost column (31-34). relay.go gives N × (N − 1) sends under maxPeers 0; spec §9.4 prices the copies ("N − 1 copies … about 0.13 s of CPU per full block with 4 banks and 0.85 s with 21"). A copy of a vote or certificate is dropped before any check; a copy of a payment, update or name request gets its full check, signatures included, before the loop finds it pooled (checkPayment, checkUpdate, checkNameRequest run before contains); a name request costs up to 3 signature checks per copy. Add to the Relay bullet: "Relaying is not free. With maxPeers 0 a message travels N × (N − 1) times, and each node receives about N − 1 copies. A copy of a vote or certificate is dropped before any check, and a copy of a proposal once it is read and decoded (up to 2 MiB). A copy of a payment, update or name request is checked in full, signatures included, off the loop: about 0.13 s of CPU per full block of payments with 4 banks and 0.85 s with 21 (spec §9.4)."
