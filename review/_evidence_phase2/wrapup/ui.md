UI AREA: hand-off review report (wallet, admin page, Requests page)

UI-1 wrong (docs and code comments, with a code option): the counter's guarantee "whatever a node reports" does not hold across a restart.
- ui/README.md "The payment counter" 104-106 ("…never puts two signed payments for one block into the world, whatever a node reports"); docs/reading-the-code.md 759 ("The wallet never puts two signed payments or updates for one block into the world."); ui/wallet.go walletState.LastPaymentBlockID comment 110-112 ("…whatever any node reports"); findings.md 286 and findings_20261027.md 449-450 ("a false [height] can only make the payment miss its block").
- Code: nextPaymentBlockID drops a counter that an earlier run left more than 2×blockSlack past height + lookahead (blockID = window). Its height is the unverified /hdls/status answer, and height() takes the first answer of a run as it is; only upward jumps are bounded.
- Evidence (throwaway test with the suite's statusNode helper): run 1, node at height 1000: names block 1003. Restart; the node answers 900: names 903. 150 ms later the node answers 1000: names 1003 again. A dishonest reference node that kept run 1's payment for 1003 now holds the same-block pair the findings.md attack needs to burn the balance.
- Fix, docs: state the exception. Fix, code (owner's choice): take the payment height from the verified checkpoint (State.Height + 1), which Send and UpdateAccount already hold, instead of /hdls/status; that closes every route. At the very least never go below saved.NewestHeight + 1.

UI-2 wrong (templates): when no state verifies, the pages say "not registered". ui/README.md "Its name" (66-70) and spec §7.2: "not registered" means the verified state has no account with this key. The render read-error path leaves Name, Becomes and LastName empty; wallet.html 42-45 then prints "not registered: this key is not the key of any name on the ledger. Register it at your bank, on the Requests page." and requests.html 50 "not registered". Seen with a wallet pointed at a dead node, and with a wallet whose .trust no longer matches (the Q17 case the FAQ covers): the error, then "not registered … Register it at your bank", next to a "Freeze alice" button; the admin page showed "block interval 0 ms … total power 0, quorum 0" and "This wallet is not a validator". TestFreezeWorksWhenNoStateVerifies checks the button but not the false text. Fix: show the not-registered branch only after a verified state ({{else if .Height}} in wallet.html, {{else if .Fee}} in requests.html); otherwise "No verified state: this page cannot show your name or balance."

UI-3 missing (docs and messages): a new pin list needs a wallet restart, and no doc says how a bank makes its list. ui/README.md pin bullet 54 ("until the bank's new list replaces the file"); USER_MANUAL.md 150-152 ("ask your bank for its new list, which replaces wallet.json.trust"); ui/trust.go error at 129 and first-use log at 138 say only "replace that file"; spec §7.2: the bank hands over a new list. Code: loadPin runs only in LoadOrCreateWallet (wallet.go:83); verifiedState uses the pin in memory. Replacing a running wallet's .trust changed nothing until a restart, both ways. The pin is taken at the first page load, not at start (demo wallet started 12:17:42, logged "pinned … (first use)" at 12:21:36 when its page was first opened), so the README's "make that first start at your bank" is imprecise. With an old pin, receipts from a re-keyed bank holding under a third of the power show no ✓ (pinnedKey returns the old key); no doc says so. Neither the manual nor the runbook says how a bank produces the list. Fix: README "…and the wallet is restarted: it reads the file only at start."; manual FAQ "save it as wallet.json.trust and restart the wallet."; trust.go error "…and restart the wallet"; README or runbook: "A bank's list is the .trust its own wallet pinned against its own node; after a re-key, delete it, restart that wallet, open its page once, and hand out the new file."; manual step 1: "start it and open its page at your bank".

UI-4 wrong comment, C12-class code gap: status()'s comment (wallet.go 352-354) "Like every answer of a node the wallet does not trust, it is refused with a status of 300 or more, and read only up to maxStatusBytes". Send (line 469) decodes the receipt with json.NewDecoder(response.Body), no size bound (only the 5-second timeout). verifiedState never checks the status code. Fix: read the receipt through io.LimitReader (a receipt is about 4.6 KB; a bound such as 16 KiB; maxStatusBytes 4 KiB is too small); reword the comment, or add the status check to verifiedState.
