SIG-1 missing (most important): no doc warns against running one validator key on two nodes. docs/operating-a-network.md node config and sign-log list (201-216); docs/signature.md "The sign log" (97-128); docs/README.md line 7 ("the sign log that keeps a node from signing twice"); cmd/server/main.go 25-51. The sign log is a plain, unlocked file (writeSignLog, loadSignLog) and protects only its own process. Two nodes holding one key (a hot standby, a copied data folder, a second start by mistake) each build their own candidate, sign, double-sign, and the bank's name is frozen. ui/USER_MANUAL.md has "One key, one machine" for wallets; the node docs nothing. Evidence: cmd/server calls node.Open and Start before ListenAndServe; a second bin/server on the same node.json while the first ran (port 18380) logged "hypernode node up…" (its loop running), and only then failed with "bind: address already in use". Fix (doc): first sign-log bullet in operating-a-network.md: "Run each validator's key on one node only, one copy at a time: no hot standby, no copied data folder running. The sign log keeps only its own node from signing twice; two nodes with one key double-sign, and the name is frozen." Optional code, about 3 lines: bind with net.Listen before node.Start.

SIG-2 missing: a re-genesis unfreezes every frozen name. operating-a-network.md "Starting a new network" step 3 (267-268) says only "A pending change or a frozen mark does not carry over"; README "Cryptographic agility" (124-125) "only the keys and the network id change". GenesisAccount has no frozen or pending fields; ValidateGenesis builds every account unfrozen. A name frozen because its key leaked comes back unfrozen under whatever key the genesis writer copies, possibly the thief's. Fix: step 3 adds "A frozen name comes back unfrozen: give it a key its rightful holder made, or leave it out until the ⅔ decide." README: "…carry over; the keys and the network id change, and frozen marks and pending changes do not carry over."

SIG-3 missing: nothing says to protect plaintext private-key files. operating-a-network.md "Generate keys" (39-51) and "The node config"; ui/README.md says the key file has mode 0600. node.json holds the seed in plaintext, and so does a hand-written wallet.json. The wallet writes 0600 only for files it writes (saveKey); rewrites a hand-written file only when it seals it; load never checks modes. Evidence: hand-written wallet.json (0664), wallet started without a terminal: loaded, warned "stored UNENCRYPTED", file stayed 0664. Fix: add to "Generate keys": "node.json, and a key file you write by hand, hold the private key in plaintext: make each readable by its owner only (chmod 600 node.json wallet.json)."

SIG-5 wrong/unclear: operating-a-network.md 279-283 "A release that changes neither can roll node by node. Still, run one release on every node…". ContentHash hashes the re-marshalled JSON of the block content (ledger/hash.go), the block hash covers it, votes sign the block hash. A release that only adds an unsigned field to a message type, or changes the block hash layout, changes neither the state digest nor any signed fields, yet old and new nodes cannot agree. Fix: "A release that changes the state digest, the block hash (its layout, or the JSON of a block's content: any field of a message type) or a signed preimage … Never roll it node by node. Only a release that changes none of these can roll node by node."
