MEDIUM: a dishonest node could stop the wallet from ever saying "your freeze did not land". docs/security.md says the wallet "reports a freeze that did not land"; ui/USER_MANUAL.md: "If block N passes and your name is not frozen, the page says the freeze did not land" — the mitigation against a bank that colludes with a thief. ui/wallet.go Wallet.Freeze took blockID = wallet.height() + lookahead from the node's unverified /hdls/status even when a verified state was available; height() puts no cap on its first answer and lets the reported height grow by 32 blocks plus 1 per millisecond; freezeStatus says "did not land" only once a verified state reaches blockID. Attack: a thief and a colluding bank file a key change; the customer presses Freeze; the bank's node reports a huge height, answers 202 and drops the freeze; the page shows "sent, not confirmed" indefinitely and the key change lands. Evidence: two tests failed (the verified state at 9, the freeze named block 1000000003, and at verified height 500 the page still said only "sent"; 200 ms after one honest answer the freeze named block 195, outside the 10-74 window). Fix (about 14 lines, prototyped): when a state verifies, take the height in progress from it (State.Height + 1), as Send does; fall back to wallet.height() only when no state verifies. FIXED on the branch (TestFreezeNamesItsBlockFromTheVerifiedState).
